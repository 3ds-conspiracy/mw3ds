# Native test build

Runs the scripted story tests (`tools/test/cases/*.txt`) against the game built for the PC: no emulator, no 3DS timing
or memory limits. A case that takes minutes on Azahar takes seconds here.

## How it works

- `build.py` compiles the game's own `source/*.cpp` with zig (`python -m ziglang`), against stand-in 3DS headers in
  `stub/`. zlib is downloaded once into `build/native/zlib`. Output: `build/native/mw3ds-native.exe`.
- `main_native.cpp` is a **copy** of `source/main.cpp` with one change: it exits when the script ends. `source/` is
  never edited by this build.
- `native_stubs.cpp` and `stub/` stand in for what the 3DS provided:
  - `sdmc:/3ds/mw3ds/...` maps to a folder (`NATIVE_SD`, default `build/native/sd`); `.../data` maps to the converted
    game data (`MW3DS_DATA`, e.g. `out/world`), read in place.
  - Rendering, audio playback and the dev updater do nothing. Sound buffers finish the moment they are queued, and
    every texture counts as loaded.
  - There is one thread: the streaming thread is off, and the game's own "no thread, load it now" path runs instead.
  - The log is written to the same `log.txt` format, so the same scripts read it.
- Numbers match the 3DS on purpose: floating-point fusing is off (`-ffp-contract=off`; the 3DS rounds every
  operation, and a host-CPU build rounded some `(int)` truncations the other way), and `rand()` is devkitARM's newlib
  generator (same sequence, `RAND_MAX` 0x7fffffff). Cases that roll unseeded dice (`ROLL:-1`, no `SEED:`) can still
  pass or fail from run to run on either side: `mech-enchant` did on the emulator too.
- The case files and their parser are the same as on the emulator. Scripted steps use the fixed `dt = 1/30`, so
  the run does not depend on real time.

## Commands (from the repo root)

Build (only needed after changing `source/`; the runner builds if the exe is missing):

```powershell
python tools\test\native\build.py
```

One case:

```powershell
tools\test\run-test.ps1 mq-ch1 -Native -Data out\world -Start 'Seyda Neen'
```

All cases, several at a time, with a saved summary:

```powershell
powershell -NoProfile -File tools\test\run-native-all.ps1 -IgnoreWarnings
```

## Flags

`run-test.ps1` (one case):

| Flag | Meaning |
|---|---|
| `-Native` | Run the PC build instead of the emulator. |
| `-Sd <folder>` | Own SD folder for this run (default `build\native\sd`). Needed to run cases in parallel. |
| `-Data <folder>` | Converted game data (default `out\data`; the main quest needs `out\world`). |
| `-Start <cell>` | Start cell (default `Balmora`; use `'Seyda Neen'` for story cases). |
| `-Wait <sec>` | Give up after this many seconds (default 300). |
| `-Fast` | Emulator only: no speed cap, no vsync for the run; the ini is put back afterwards. |

`run-native-all.ps1` (all cases):

| Flag | Meaning |
|---|---|
| `-Filter a,b` | Only cases matching these wildcards, e.g. `'mq-ch*','bug-*'`. Default: every case except `chain-*`. |
| `-Jobs <n>` | Cases at a time (default: logical cores minus 2). Each gets its own `build\native\sd-<slot>`. |
| `-Data <folder>` | Default `out\world`. |
| `-Start <cell>` | Default `'Seyda Neen'`. |
| `-Wait <sec>` | Per-case limit (default 600). |
| `-Build` | Rebuild the exe first. |
| `-IgnoreWarnings` | `monitor:` warnings do not fail a case. Failed expectations, driver failures and runs that crash or time out still do. |

`chain-*` cases are generated by `run-suite.ps1 -Chained` and each needs the save from the one before, so they are left
out unless named in `-Filter`.

## Output

`build\native-results\<timestamp>\`, and the newest run is also copied to `build\native-results\latest\`:

- `summary.txt`: cases that succeeded (with how many warnings were ignored) and the ones that failed with their reasons.
- `results.csv`: one row per case: result, seconds, warnings, detail.
- `logs\<case>.log`: the game log of each case.
- `out\<case>.txt`: what `run-test.ps1` printed for each case.

## What to trust

Compared with the emulator on a few cases, the expectation counts and navigation warps matched.

Good on native: quest and journal progress, scripts, dialogue, formulas, saves, navigation, and `expect:` checks.

Not checked natively, so use the emulator:

- Missing textures (every texture "loads").
- Linear memory and heap warnings (the heap here is a stand-in).
- Crashes from unmapped reads, GPU and rendering behaviour.
- Floor and collision monitor warnings can differ slightly: the PC uses x86 floating point and the 3DS uses ARM, so
  positions drift by a few units. A `monitor:` warning on only one side needs a look, not an automatic fail.
- Checks that depend on rendering or water data (for example `refwater`) may report `unknown check`.

A native pass is a fast regression check. Run the emulator for a final check before a release.

## Keeping the copy in step

`main_native.cpp` does not follow `source/main.cpp` by itself. When `main.cpp` changes, re-copy it and re-apply the exit
after `autoinput: end` (search for `native test build`). There is no automatic drift check yet.
