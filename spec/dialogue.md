# Dialogue

Which response an actor says, and what a conversation does around it. Read from OpenMW's
`apps/openmw/mwdialogue/{filter,selectwrapper,dialoguemanagerimp,keywordsearch,topic,journalimp,quest}.cpp` and
`components/interpreter/defines.cpp`, with the sorted-order note taken from `mwworld/store.hpp` / `store.cpp`
(the Dialogue store). In our words. "Info" is one response record inside a topic (a `DialInfo`); a topic's infos are
tried in file order, and that order is the whole priority system.

Test: `openmw-spec-dialogue` (generated by `tools/test/specgen_dialogue.py`). What the oracle cannot judge yet, and the
hooks the engine would need, is in `spec/findings/dialogue.md`.

## A. Choosing a response (filter.cpp)

**R1. First match.** `Filter::search(topic, fallbackToInfoRefusal)` walks the topic's infos in order and returns the
first one that passes four tests, in this order: the speaker (R3), the player (R4), the Select conditions (R5), then
the disposition (R6). Nothing is scored: an earlier info always wins over a later one that would also pass. `list()`
is the same walk that keeps every match (used for the service refusal, R17).

**R2. Info Refusal fallback.** An info that passes the speaker, player and condition tests but fails only on
disposition marks the topic "refused". If no info at all matched and the topic was refused, and the caller allowed
the fallback, the walk is repeated over the topic named "Info Refusal" with the same four tests, and its first match
is the answer. Callers that allow it: clicking a topic, answering a choice, building the topic list (R20).
Callers that do not: greetings, voiced reactions. A response that came from Info Refusal is never written to the
journal's topic history (R23).

**R3. Speaker tests (`testActor`).**
- Speaker id: if the info names an actor, only that actor passes. An info naming nobody is rejected for every
  creature: creatures only ever say infos that name them.
- Race, class: must equal the NPC's. For a creature the test is skipped and passes ("return true" ends the whole
  speaker test early, so the faction, rank and gender tests are skipped too).
- Faction: an info flagged "no faction" (id FFFF) fails when the NPC has a primary faction. An info naming a faction
  needs the NPC's primary faction to be that one, and then the NPC's rank in it must be at least the info's rank.
  An info with a rank but no faction compares the rank with the NPC's own primary-faction rank (an NPC with no
  faction counts as rank -1, so a rank requirement fails). A "no faction" info ignores its rank field.
- Gender: the info's gender byte (0 male, 1 female, -1 either) fails when it is the opposite of the NPC's sex;
  creatures skip it.

**R4. Player tests (`testPlayer`).**
- Player faction: an info naming one needs the player to be a member, with rank at least the info's PC rank. No
  rank can be below -1, so "any rank" passes for every member.
- PC rank without a faction named: the player must be a member of the SPEAKER's primary faction and at least that
  rank (a speaker with no faction fails it).
- Cell: the info's cell name must be a case-insensitive prefix of the PLAYER's current cell name (not the speaker's).

**R5. Select conditions (`testSelectStructs`).** All must pass; each is `function, comparison, value`. Comparisons
are the six: equal, not equal, greater, greater or equal, less, less or equal. Two rules apply before any function:
- `Choice` (any comparison) fails when no choice is in progress (the filter's choice is -1). During a choice it
  reads the number picked.
- `Weather` fails in any interior cell (exterior and quasi-exterior pass). OpenMW notes the original game did not
  have the quasi-exterior exception.
Functions fall in four kinds: integers (R7-R11), "numeric" ones (global, local, health-like: compared as floats),
booleans (compared as 0 / 1 against the stored value, so `= 0` means "false"), and the five "Not" tests (R12).
The condition kinds read from the record besides the numbered functions are Global, Local, Journal, Item, Dead and
the Not family.

**R6. Disposition (`testDisposition`).** Creatures always pass. For an NPC the actor's DERIVED disposition (base,
race / faction / reputation modifiers, effects, current persuasion) must be at least the info's disposition number.
Inverted form for service refusals (R17): passes when the info's number is 0 or the derived disposition is below it.

## B. What each Select function reads (filter.cpp getSelectStruct*, selectwrapper.cpp)

The two-digit code is the ESM function number; `selectwrapper.cpp` maps each to the AI setting, attribute or skill
index it reads. "PC" = the player; "NPC" = the speaker.

**R7. Player attributes and skills.** Codes 10 and 51-57 (Strength, Intelligence, Willpower, Agility, Speed,
Endurance, Personality, Luck) and 11-37 (the 27 skills, Block first, Hand to Hand last) read the player's MODIFIED
value, truncated to a whole number. 6 = player level, 5 = player reputation, 43 = player bounty (the crime level),
38 = player gender (0 male, 1 female).

**R8. Player bars.** 7 = player health percent: the health ratio x 100, truncated to an integer. 8 = magicka,
9 = fatigue, 64 = health: the CURRENT absolute value as a float (not a percent).

**R9. NPC values.** 3 = the NPC's reputation (0 for creatures). 4 = NPC health percent (ratio x 100, truncated).
61 = NPC level. 67 / 68 / 69 / 70 = the NPC's Fight / Hello / Alarm / Flee AI setting, the modified value (Hello is
the greeting-range number: a Hello of 0 or 30 is just compared).

**R10. Factions.**
- 46 (Same Faction) = the player is a member of the NPC's primary faction (false for an NPC with none).
- 47 (Faction Rank Difference) = the player's rank in the NPC's primary faction MINUS the NPC's rank; 0 when the
  NPC has no faction. A non-member has rank -1 (to be confirmed, see findings).
- 0 / 1 (Reaction Low / High) = over every faction the player belongs to, the lowest / highest reaction the NPC's
  primary faction holds towards it (reaction overrides set by script count), starting from 0 so Low never exceeds 0
  and High is never below 0; 0 when the NPC has no faction.
- 2 (Rank Requirement) = a bit mask for the player's NEXT rank in the NPC's faction: +1 if the player's skills and
  the faction's two attributes (base values) reach that rank, +2 if the player's faction reputation does; 0 when the
  NPC has no faction or the player is already rank 9.
- 39 (PC Expelled) = the player is expelled from the NPC's faction (false with none).

**R11. State flags and counters.**
- 40 / 41 = the player has a common / blight disease. 58 = Corprus effect magnitude not 0. 60 = Vampirism effect
  magnitude above 0 (the effect, not a script variable).
- 42 (Clothing Modifier) = the sum of the base VALUE of whatever the player wears in inventory slots 0 to 15 (so
  not held weapons or ammunition; shield and lights are outside that range too).
- 44 / 45 = same sex / same race as the NPC (both false for a creature).
- 48 Detected = the awareness check of player against NPC; 49 Alarmed = the NPC's alarmed flag; 62 Attacked = the
  NPC's attacked flag; 71 Should Attack = the NPC would be aggressive to the player now; 72 Werewolf = the NPC is
  a werewolf; 73 PC Werewolf Kills = the player's kill count.
- 63 Talked to PC = whether the NPC had talked to the player when this conversation STARTED (frozen, R14).
- 65 Creature Target = what the NPC is fighting: 2 a werewolf, 1 a creature, 0 nothing or anything else.
- 66 Friend Hit = the NPC's count of friendly hits, capped at 4.
- 59 Weather = the current weather's script id (outdoors only, R5).
- 50 Choice = the picked choice number (R5).
- Dead (kind): how many of that id have died (the mechanics manager's death count); Item: how many the PLAYER's
  inventory holds of that id; Journal: the quest's index (R22), 0 when never started.

**R12. The "Not" family.** Not ID, Not Faction, Not Class, Not Race, Not Cell are Boolean tests whose
comparison operator and value are IGNORED: only the plain truth counts (not that id / the faction is different / the
class is different / the race is different / the speaker's cell name does not start with that name). A creature is
"not" every class and race. Not Faction compares with the primary faction (an NPC with none is not any faction).

**R13. Globals and locals.**
- Global: if no such global exists, the condition is ignored (passes). Otherwise it is compared as a float.
- Local / Not Local read the SPEAKER's script variables: no script or no variable of that name makes Local false
  (and Not Local true: it is the negation of the plain local test, comparison included, not a separate rule). A
  speaker whose script has not run yet reads 0. Value types short / long / float.

**R14. Talked-to-PC is frozen.** `startDialogue` reads the NPC's "has talked to the player" flag once and keeps it
for the whole conversation; the greeting sets the NPC's real flag, but the conversation's filter keeps the old
value until the next conversation. The voiced-reaction path (`say`) reads the live flag instead.

## C. Conversation flow (dialoguemanagerimp.cpp)

**R15. Greetings.** `startDialogue`:
1. A dead actor cannot be talked to.
2. The Dialogue store is iterated in SORTED id order (`mwworld/store.cpp`, "sorted for unknown reasons"), so the
   Greeting topics are tried as "greeting 0", "greeting 1" ... "greeting 9", lowest first.
3. Each Greeting topic is searched without the Info Refusal fallback; the first topic with a match supplies the
   greeting (so Greeting 0's matching info beats everything below it, and a topic's own infos are in file order).
4. If no Greeting topic has a match, there is no conversation (the call returns false).
5. On a match: the NPC is marked talked-to-player; the response text goes through % substitution (R26) and is
   shown; the info's result script runs; the greeting's topic becomes the "last topic" (what a choice answers, R19);
   then topics named in the RAW text are learned (R21: after the script).
The conversation-start also refreshes the engine-maintained dialogue globals first (crime gold values; see
the findings, F9 in `audit-findings.md`).

**R16. Clicking a topic.** `keywordSelected` does nothing while a choice is open (R19) and ignores any name that is
not a Topic-type dialogue. Otherwise `executeTopic`: search the topic with the Info Refusal fallback (choice -1); if
there is an info, show it with the title (R18); for a Topic-type dialogue whose answer came from the topic ITSELF,
record the info in the journal's topic history (R23); remember the topic as the last topic; run the result script;
then learn topics from the raw text (R21). No answer: nothing happens.

**R17. Service refusal.** Before an NPC offers a service, `checkServiceRefused` runs the Service Refusal topic with the
SERVICE TYPE as the filter's choice number (so `Choice = n` conditions in that topic select the refusal for the
service), the disposition test inverted, no Info Refusal fallback and "first match" only. If it matches, the answer
is said with the title from GMST `sServiceRefusal`, its script runs, and the service is denied.

**R18. Response titles.** An ordinary topic shows the topic's own name. A Persuasion-type dialogue (Admire, Intimidate,
Taunt, Bribe, each Success / Fail) shows the GMST named "s" + the topic id with spaces removed
(`sAdmireSuccess`, `sBribeFail` ...).

**R19. Choices and Goodbye.** The `Choice` script command adds a button and puts the conversation "in choice": topic
clicks are ignored until it is answered. `questionAnswered(n)`: the filter's choice becomes n and the LAST topic
(greeting or ordinary topic only) is searched again with the Info Refusal fallback; Choice conditions now compare
with n. If an info matches, the choice state is cleared, the text shown, its topics learned, its script run, and
journal history added as in R16. If none matches, the choice state is cleared and nothing is said. The topic list is
rebuilt afterwards. `Goodbye` (script command) closes the choice state and flags the conversation as ended.
Leaving ("goodbyeSelected") makes persuasion's PERMANENT part of the disposition change stick, clamped so the derived
disposition stays within 0-100 and not below what intimidate leaves; the temporary part and Charm are dropped.

**R19b. Which info answers a choice (as OpenMW and the original game).** The first info of the topic that fits
with the choice number set answers, whether or not it tests Choice. A plain info listed before the Choice infos can
win: Milyn Faram's "Odirniran" question sets HT_Odirniran to 50, so after "Listen to what he has to say" (Choice 2)
the "so much happier here" line (Journal >= 50) answers and the scroll reward (journal 60) is never reached. UESP lists
this as a bug of the original game, fixed only by the Morrowind Patch Project mod; we keep it. Test:
`bug-choice-answer-first` (expects the original game's line).

**R20. Voiced reactions (`say`).** For Hello, Attack, Hit, Flee, Thief etc.: refused when the actor is already
speaking, an NPC is swimming, or the actor is knocked down. Otherwise the topic is searched with choice 0 (not -1),
the live talked-to flag, and no Info Refusal fallback; a match shows the subtitle, plays the sound, runs the script.

## D. The topic list (dialoguemanagerimp.cpp `updateActorKnownTopics`, `getAvailableTopics`)

**R21. What is listed.** For every Topic-type dialogue, search it for the speaker (choice -1, frozen talked flag,
Info Refusal fallback allowed). The topics with an answer are the "actor-known" topics. The list shown is those the
PLAYER also knows, sorted case-insensitively by name. So a topic whose only answer is an Info Refusal is listed
(and clicking it says the refusal).

**R22. Learning topics.** The player learns a topic when it is named in a response text (greeting, topic answer,
choice answer, service refusal) AND the speaker has an answer for it (R21). Matching (`keywordsearch.cpp`): the text
is split around explicit links `@name#` (always a hit, named by what is between the markers, case folded); the rest
is searched for any topic name that starts at the beginning of the text or right after one of newline, return, space,
tab, apostrophe, double quote, "(" or "[". The END of the keyword is not checked ("work" matches inside "workshop").
Overlaps resolve by taking the longest match first (the first of equals), dropping what overlaps it, repeating. The
search uses the raw text, before % substitution. It runs AFTER the result script, so topics the script's
`AddTopic` just taught are already known.

**R23. Exhausted and specific topics.** For each actor-known topic: if the info chosen is already in the player's
journal topic history for that topic, it is "exhausted"; otherwise if the info names this very actor it is
"specific". An exhausted topic loses the flag again when its answer's text names a topic the speaker can answer and
the player does not yet know. (OpenMW only draws these as colours when a setting is on; the rule is the flag.)
The history keeps one entry per info id: hearing the same info twice adds nothing (`topic.cpp`).

**R24. Journal index (`quest.cpp`, `journalimp.cpp`).** A quest's index is 0 until started. Adding a journal entry
sets the index to that entry's number only when it is higher than the current one; `SetJournalIndex` sets it directly,
up or down. A Journal select condition reads this index. A script-added entry that already exists changes nothing
but may raise the index and shows the notice only then.

**R25. Topic links in the journal (`mwgui/journalbooks.cpp`, `journalviewmodel.cpp`).** The journal's text (its
entries, and what was said about a topic) shows the topics the journal has, found as in dialogue (keyword search,
longest match), as links; following one opens that topic's page. A topic page's own name is not a link. On the 3DS: a
tap on the link opens the topic in the Topics tab; Back returns to the index. The Search button (ours, not
OpenMW's) narrows the index to topics whose name holds the text and the entries to those that do. Test: `issue-26`.

## E. Text substitution (components/interpreter/defines.cpp, dialogue mode)

**R25. Escape characters.** `%` and `^` both start a substitution. After the escape character the following text is
compared, ignoring case, as a PREFIX with this table, in this order, first hit wins: the action-key names
(ActionActivate ... , not meaningful in dialogue text); PCCrimeLevel (the bounty as a whole number); then, for
dialogue: NextPCRank, PCNextRank, Faction, PCClass, PCName, PCRace, PCRank, Class, Cell, Race, Rank, Name. Because it is a prefix match, "%Classy" is "<class name>y". "%PCClass" and "%Class"
differ: PC... is the player, the plain ones are the NPC (Faction, Class, Race, Rank, Name) except Cell = the current cell.
If nothing in the table matches, global variables are tried, longest name first, printing a short or long as an integer
and a float with the stream default (6 significant digits).

**R26. Not found.** An escape char with no match is printed as itself, and the character right after it is never
examined as an escape char (so "%%name" prints "%%name"). The text after the last substitution is copied as is.

**R27. Values the table reads** (the interpreter context, not re-read for this page: confirm in the findings): the
player's name / race / class / rank in the NPC's faction / next rank; the NPC's name, class, race, faction and rank
names; the cell name. A missing faction or a rank out of range prints empty or "%" depending on the getter (the audit
lists this as F29).

**R28. Substitution happens at display only.** The topic scan (R22) and the stored journal text use the raw text.

## F. Tolerances the oracle uses

A condition about state the harness cannot set or read yet (the player's race and sex, worn clothing, exact item
counts, speaker locals that a script writes, Detected, Should Attack, absolute magicka / fatigue) is "unknown": a case
whose first match depends on it is not written. See `spec/findings/dialogue.md` for the hooks that would turn those
into tests.
